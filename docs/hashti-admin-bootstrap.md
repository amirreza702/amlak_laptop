# راه‌اندازی اولیه مدیر ارشد هشتی

این راه‌اندازی فقط یک‌بار انجام می‌شود و از endpoint عمومی ثبت‌نام استفاده نمی‌کند.

## ۱. آماده‌سازی محیط

در محیط اجرای backend متغیر `HASHTI_BOOTSTRAP_SECRET` را با یک مقدار تصادفی و طولانی تنظیم کنید. این مقدار نباید در Git، فرانت‌اند، URL یا لاگ‌ها قرار گیرد. برای نمونه در PowerShell مقدار نمونه را با secret واقعی جایگزین کنید:

```powershell
$env:HASHTI_BOOTSTRAP_SECRET = "<SECRET_RANDOM_AND_LONG>"
```

اگر backend داخل Docker اجرا می‌شود، این متغیر باید از طریق تنظیمات محیطی همان سرویس به کانتینر تزریق شود و سپس سرویس backend با آن محیط راه‌اندازی شود.

## ۲. اعمال تغییرات دیتابیس

این تغییرات یک migration افزایشی برای ستون‌های مجوز مدیریتی و جدول `admin_audit_logs` فراهم می‌کنند. پس از اعمال schema، دستور `npx prisma generate` را در پوشه backend اجرا کنید تا Prisma Client با فیلدهای جدید همگام شود. قبل از اجرا، از دیتابیس موجود نسخه پشتیبان بگیرید و وضعیت migrationهای موجود پروژه را بررسی کنید. این فایل به‌تنهایی baseline دیتابیس قدیمی نیست و نباید روی دیتابیس خالی به‌عنوان اولین migration اجرا شود. این تغییر در کد به‌صورت خودکار migration را اجرا نمی‌کند.

## ۳. ایجاد مدیر ارشد

پس از اعمال migration و تنظیم secret، از یک محیط مدیریتی امن درخواست زیر را ارسال کنید. رمز باید حداقل ۱۲ کاراکتر باشد:

```powershell
$body = @{
  mobile = "09123456789"
  password = "<INITIAL_PASSWORD_MIN_12_CHARS>"
  secret = $env:HASHTI_BOOTSTRAP_SECRET
} | ConvertTo-Json

Invoke-RestMethod -Method Post `
  -Uri "http://localhost:4000/auth/admin/bootstrap" `
  -ContentType "application/json" `
  -Body $body
```

این endpoint فقط زمانی حساب مدیر ارشد می‌سازد که هنوز هیچ حسابی با `isSuperAdmin=true` وجود نداشته باشد. تراکنش Serializable از ایجاد هم‌زمان بیش از یک مدیر ارشد جلوگیری می‌کند. پس از ایجاد حساب، secret را از محیط‌های موقت حذف کنید و با همان شماره موبایل از مسیر عادی ورود استفاده کنید.

## مجوزهای کارکنان

- `USERS_READ`: مشاهده فهرست و جزئیات کاربران
- `USERS_MANAGE`: فعال/غیرفعال‌کردن حساب‌ها
- `OWNERS_MANAGE`: مدیریت مالکان و سوابق
- `AGENTS_MANAGE`: مدیریت تأیید و اشتراک مشاوران
- `STAFF_MANAGE`: ایجاد حساب کارمند و تنظیم مجوزهای آن
- `AUDIT_READ`: مشاهده سوابق مدیریتی

هر تغییر وضعیت، تأیید مشاور، ایجاد/ویرایش مجوز کارکنان یا ایجاد اشتراک در همان تراکنش با سابقه ثبت می‌شود؛ در صورت شکست ثبت سابقه، تراکنش تغییر نیز rollback می‌شود.
